## 2. 审计发现清单

### 1. 定时备份从不读取剩余磁盘

- **文件与行号**：`scripts/backup.ts` 第 14–18 行；`cli/index.ts` 第 208–212 行；`src/services/backup.ts` 第 236–241 行
- **严重等级**：高
- **问题描述**：`runDailyBackup` 只有调用方传入 `diskFree` 才记录剩余空间。`npm run backup` 和 CLI 的 `backup` 都没有传。成功和失败的 `disk_free_bytes` 都是空，`disk_warning` 恒为 false。低于 3GB 时不会打印告警，管理界面也看不到剩余空间。集成测试自己注入了 `diskFree`，所以测试能断言告警，定时任务却测不到这条路径。
- **修复建议**：在 `scripts/backup.ts` 和 CLI 里用备份目录所在磁盘的可用字节数实现 `diskFree`，并在没有注入函数的测试里断言 `backup_record.disk_free_bytes` 不是空。

```ts
import { statfs } from 'node:fs/promises';

diskFree: async (dir) => {
  const info = await statfs(dir);
  return Number(info.bavail) * Number(info.bsize);
},
```

### 2. 咨询锁解锁失败时，锁会留在连接池里

- **文件与行号**：`src/repo/db.ts` 第 112–119 行
- **严重等级**：中
- **问题描述**：`pg_try_advisory_lock` 占住的是从池里借出的那条连接。解锁查询若失败，`finally` 仍把这条连接还回池，会话锁还在。之后从池里拿到它的请求继续持有备份锁或检查点锁，别的任务一直看到 `busy`，直到这条连接被销毁。
- **修复建议**：解锁失败时 `client.release(err)` 丢掉这条连接，不要还回池。进程退出或连接断开时，PostgreSQL 会释放会话锁。

### 3. 账本里无法识别的条目被静默丢掉

- **文件与行号**：`src/services/anonMaintenance.ts` 第 160–166 行
- **严重等级**：中
- **问题描述**：`reapplyAnonLedger` 遇到不是 UUID、处理版本不合法或代号过长的条目时直接 `continue`。它们不算 `missing`，也不算 `pending`。预览会显示「没有待补做」，恢复后的学生却仍带着姓名。重试失败后的状态更新用空的 `catch` 吞掉，导出表可能一直停在 `pending`，而命令输出已经写成失败。
- **修复建议**：无法识别的条目计入单独的 `rejected` 并让命令以非 0 退出。状态更新失败时把原始错误打到日志，不要吞掉。

### 4. `pg_dump` 没有超时

- **文件与行号**：`src/services/backup.ts` 第 96–112 行
- **严重等级**：低
- **问题描述**：子进程若既不退出也不报错，会一直占着咨询锁和一条数据库连接。下一次定时备份只能跳过。失败记录也不会写上。
- **修复建议**：超过时限就 `child.kill()`，把「超时」写入 `backup_record.error`，退出码为 1。

## 4. 给开发会话的修复指令摘要

`npm run backup` 和 CLI 的 `backup` 必须测量备份目录所在磁盘的剩余字节，写入 `backup_record.disk_free_bytes`，低于 3GB 时在日志里告警。不要只在测试里注入 `diskFree`。咨询锁解锁失败时丢掉那条连接。账本里无法识别的条目要计成失败，不能从预览里消失。
