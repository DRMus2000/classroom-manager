## 2. 审计发现清单

### 1. 回放名次用明细序号冒充事件序号

- **文件与行号**：`src/services/replay.ts` 第 110–132 行
- **严重等级**：高
- **问题描述**：`rankingAt` 用 `point_entry.seq <= event_seq` 决定某一帧包含哪些明细，破并列又取 `MAX(point_entry.seq)`。设计写明 `last_change_seq` 是该批次的 `event_log` 序号，不是明细自己的序号。两条序列各自增长，帧上的分数和名次会对错人、对错时刻。`cumulative` 与 `net` 走的是同一段求和，`mode` 没有改变结果。
- **修复建议**：用该批次写入的回放事件序号过滤和破并列。`net` 只累计区间内的 `delta`，`cumulative` 还要加上区间开始前的余额。

```sql
AND pe.seq <= ${uptoSeq}
```

改为与记分时写入 `point_balance.last_change_seq` 的那个 `event_seq` 比较，不要和 `point_entry.seq` 比较。

### 2. 历史帧用的是现在的在班状态

- **文件与行号**：`src/services/replay.ts` 第 120–129 行；`docs/DESIGN.md` 第 216 行
- **严重等级**：高
- **问题描述**：查询条件是 `st.status = 'active'`，并且只 JOIN 有明细的学生。已经离班的学生会从离班前的帧里消失。匿名化学生不会显示匿名代号。设计要求每一帧取当时的在班集合：离班前仍在，离班后退出。
- **修复建议**：用 `roster_changed` 事件把每一帧的在班集合算出来，再在这个集合上做 Top10。匿名化之后的帧使用 `anon_code`。

### 3. 检查点规则没有写入路径

- **文件与行号**：`src/services/replay.ts` 第 11–14 行；`test/replay.test.ts` 第 5–16 行
- **严重等级**：高
- **问题描述**：`shouldWriteCheckpoint(200)` 为真，记分服务也确实没调用它。没有任何任务在满 200 个回放事件或每日兜底时插入 `replay_checkpoint`。时间轴接口因此永远拿不到检查点，`base_state` 固定是空数组。测试只断言了这个纯函数，并检查 `points.ts` 源码里没有对应字符串，证明不了检查点会被写进数据库。
- **修复建议**：独立任务读取 `job_config` 的阈值，按班和当前学期写入检查点。测试要在数据库里看到行，而不是检索源码。

### 4. 每一帧都全表聚合一次

- **文件与行号**：`src/services/replay.ts` 第 77–85 行
- **严重等级**：中
- **问题描述**：一页最多 200 帧，每一帧调用一次 `rankingAt`，每次都扫描该学期的 `point_entry`。这是按帧重复的全量聚合，时间轴拖动会把数据库打满。
- **修复建议**：从最近检查点的名次出发，按事件序号扫一遍区间，在内存里更新 Top10。

### 5. 排行榜改走 `listRanked` 后，没有余额行的在班学生消失

- **文件与行号**：`src/repo/points.ts` 第 489–498 行；`src/services/points.ts` 第 616–630 行
- **严重等级**：中
- **问题描述**：`listRanked` 从 `point_balance` 内连接学生。学期切换时会给当时的在班学生插入 0 分。之后新加入的学生没有余额行，不会出现在当前榜。上一版服务查询是左连接，这些人会以 0 分出现。
- **修复建议**：在班学生没有余额行时按 0 分和 `last_change_seq = 0` 纳入排序，或者在新增学生时写入当前学期的余额行。

### 6. 账本锁超过 5 秒会被另一请求删掉

- **文件与行号**：`src/services/anonLedger.ts` 第 138–141 行
- **严重等级**：低
- **问题描述**：锁文件修改时间超过 5 秒就删除。这个阈值和等待超时一样长。加密写入一旦超过 5 秒，后来的请求会拆掉仍在使用的锁。崩溃后的第一下调用仍会空等 5 秒再失败，下一调用才能清掉锁。
- **修复建议**：只删除已经没有持有者的锁，并把「视为过期」设得长于一次正常写入。

## 3. 已关闭的 002 项

- 卫生测试会取消抽选，断言抽中的人不变，并用当前版本关闭 `pending` 轮次，得到 `DUTY_SELECTION_OPEN`。重复缺席断言 `FORBIDDEN`。
- 改密幂等响应是 `{ ok: true }`。没有新令牌时不设置 Cookie。
- 空池任命会核对是本班在班学生，并广播 `duty_round_changed`。
- 冻结、取消、确认、重新打开和纠正都会核对进行中轮次的 `expected_version`。
- 当前榜改走 `pointsRepo.listRanked`。

## 4. 给开发会话的修复指令摘要

回放帧和 `state-at` 必须用记分时写入的回放事件序号，不能用 `point_entry.seq`。每一帧按当时的在班集合取 Top10，离班前仍在，匿名化后显示代号。`cumulative` 含区间前余额，`net` 只含区间内净增减。检查点由记分事务之外的任务写入，测试要在数据库里断言有行。没有 `point_balance` 的在班学生仍以 0 分出现在当前榜。
