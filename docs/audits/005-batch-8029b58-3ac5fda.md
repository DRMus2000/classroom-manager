### 1. 未推椅子的界面结论和服务端抽选不一致

- **文件与行号**：`web/src/features/duty/DutyPage.tsx` 第 83–87、30 行；`src/services/duty.ts` 的 `markNoPush`；`docs/DEVIATIONS.md` 第 10 行
- **严重等级**：高
- **问题描述**：点击「再次未推椅子」后，提示是「本轮失去替补资格」。候选预览也按 `no_push` 把此人排除。服务端只把 `duty_round_member.no_push` 写成 `true`，不把 `eligible_for_backfill` 写成 `false`。冻结和抽选用的是 `candidatesOf`，它不看 `no_push`。老师在界面上看不到的人，仍会被抽中。
- **修复建议**：`markNoPush` 在同一事务把 `eligible_for_backfill` 设为 `false`。已经冻结的轮次还要从剩余候选里移出此人，并作废抽中此人的未确认抽选。补一条集成测试：未推椅子之后冻结，候选里没有此人。

### 2. 时间字符串解析不能处理数据库已经返回的格式

- **文件与行号**：`src/services/class.ts` 第 24–31 行；`src/repo/points.ts` 第 420 行；`web/src/lib/format.ts` 第 40–44 行
- **严重等级**：中
- **问题描述**：`iso()` 直接 `new Date(value).toISOString()`。PostgreSQL 文本格式是 `2026-09-25 02:20:22.09+08`。这种字符串在 JavaScript 里常常是 Invalid Date，`toISOString()` 抛 `RangeError`，班级和学期接口变成 500。前端的 `parseTime` 会先把空格换成 `T`，并把 `+08` 补成 `+08:00`。服务端这条新路径没有同样的处理。时间线排序用的也是 `new Date`，无效时间会变成 `NaN`，顺序不稳定。
- **修复建议**：服务端使用和 `parseTime` 相同的补齐，解析失败时抛 `AppError('INTERNAL')`，不要抛 `RangeError`。

```ts
function iso(value: Date | string): string {
  if (value instanceof Date) {
    if (Number.isNaN(value.getTime())) throw new AppError('INTERNAL', '时间字段无法解析');
    return value.toISOString();
  }
  let text = value.trim().replace(' ', 'T');
  if (/[+-]\d{2}$/.test(text)) text += ':00';
  const date = new Date(text);
  if (Number.isNaN(date.getTime())) throw new AppError('INTERNAL', '时间字段无法解析');
  return date.toISOString();
}
```

### 3. `ANY()` 修复没有测试，也没有写成 uuid 数组

- **文件与行号**：`src/repo/points.ts` 第 286、388、437 行；`src/repo/student.ts` 第 319、404 行
- **严重等级**：中
- **问题描述**：`sql.param(studentIds)` 让数组作为单个参数，不再被展开成多列。参数没有 `::uuid[]`。驱动若把它当成 `text[]`，和 `uuid` 列比较仍会失败，记分批次再次整批报错。提交说明写的是每个记分批次都失败过，但这次没有一条测试在真实 PostgreSQL 上执行 `ANY(uuid[])`。
- **修复建议**：写成 `ANY(${sql.param(studentIds)}::uuid[])`。集成测试插入两名学生并记一批分，断言两条 `point_entry` 都在，且 `last_change_seq` 相同。
