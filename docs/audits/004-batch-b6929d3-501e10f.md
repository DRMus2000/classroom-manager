## 2. 审计发现清单

### 1. 触发器修复改了已经执行过的迁移

- **文件与行号**：`migrations/001_phase1_core.sql` 第 304–312 行；`scripts/migrate.ts` 第 73–79 行
- **严重等级**：高
- **问题描述**：`assert_term_open` 在拒绝时原来会 `RETURN NULL`。`BEFORE INSERT` 返回 `NULL` 会把这一行悄悄丢掉，记账看起来成功，账本里却没有明细。现在函数改为 `RETURN NEW`，拒绝时仍 `RAISE EXCEPTION`。这个改动写在 `001_phase1_core.sql` 里。迁移器发现 checksum 不符只打印警告并跳过，不会执行新的函数体。已经跑过 001 的库继续丢掉开放学期的记账。
- **修复建议**：新增 `003_...sql`，只放 `CREATE OR REPLACE FUNCTION assert_term_open()`，保持 001 的已发布内容不变。补一条迁移测试：开放学期插入 `point_entry` 能留下行，归档学期插入则失败。

### 2. 读倒计时把超时写成 finished，但不发事件

- **文件与行号**：`src/services/countdown.ts` 第 76–90 行；`test/rollcall.integration.test.ts` 第 211–221 行
- **严重等级**：中
- **问题描述**：`GET /countdown/:class_id` 发现 `running` 已过截止时间，会在事务里改成 `finished`。这次写入没有 `countdown_changed`。其他端的 SSE 仍显示在跑，直到它们自己来读。测试只断言读取结果是 `finished`，并断言事件表里存在更早的 `countdown_changed`，证明不了这次落库有广播。
- **修复建议**：状态真正从 `running` 改成 `finished` 时，同一事务写 `countdown_changed`，提交后再广播。测试在读取之前数事件条数，读取之后必须多一条，且 `payload.status` 为 `finished`。

### 3. 点名名单解析失败会变成 500

- **文件与行号**：`src/services/rollcall.ts` 第 45–52 行
- **严重等级**：低
- **问题描述**：`exclude_list` 或 `picked_ids` 若以字符串形式读出且不是合法 JSON，`JSON.parse` 会抛出普通异常，接口返回 500，而不是业务错误。`readScope` 对坏 JSON 返回空对象，两条路径不一致。
- **修复建议**：解析失败时抛 `AppError('INTERNAL', ...)` 或按空名单处理，并记下一行日志。不要让 `JSON.parse` 直接冒泡。

## 3. 这一批里已经成立的部分

- 点名池只要在班学生。离班学生不会被抽中。同一轮已抽过的人不会再抽中。排除后池空会拒绝。同一 `request_id` 重放不重复抽取，请求体不同返回 `IDEMPOTENCY_MISMATCH`。关轮后不能再抽，本班才能开下一轮。
- 倒计时运行中 `remaining_sec` 为 `null`，响应里是绝对 `deadline_at`。暂停清空截止时间并写下剩余秒数。暂停中再暂停被拒绝。继续按剩余秒数重算截止时间。
- 导出需要登录。花名册按座位号再按学号，离班学生不在表里，解析回行表后学号、姓名、座位、备注一致。`direction=add` 的导出和 `listEntries` 都只有加分行。`Content-Disposition` 会换掉引号和控制字符。
- 路由有 `requireUser`。抽取人数限制为 1 到 200。倒计时时长限制为 1 到 86400 秒。

## 4. 给开发会话的修复指令摘要

不要改 `001_phase1_core.sql`。新建迁移执行 `CREATE OR REPLACE FUNCTION assert_term_open()`，保证 `RETURN NEW`，并用测试证明开放学期的明细插得进去。`GET /countdown/:class_id` 把超时记成 `finished` 时要写 `countdown_changed`，测试要看到这一条新事件。
