## 2. 审计发现清单

### 1. 卫生集成测试没有覆盖它声称的行为

- **文件与行号**：`test/duty.integration.test.ts` 第 31、109–126 行；`src/services/duty.ts` 第 647–651 行
- **严重等级**：高
- **问题描述**：用例标题写的是「取消保留原抽选、确认后才能关轮」。测试没有调用取消，也没有造出 `pending` 抽选。空池走的是 `direct_appoint`，抽选当场就是 `confirmed`。随后用抽选之前的 `version` 去关轮，断言到的是 `VERSION_CONFLICT`。删掉「未确认不能关轮」这段检查，这个测试仍然通过。`b009a08` 把卫生任务标成完成，依据的就是这组失真覆盖。
- **修复建议**：用当前版本关一轮仍为 `pending` 的抽选，断言错误码是 `DUTY_SELECTION_OPEN`。取消后再次读取抽选，被抽中的 `student_id` 必须与取消前相同，并且不能新增第二条抽选。

```ts
const pending = await duty.drawSelection(actor, roundId, incomingId, version, requestA);
assert.equal(pending.status, 'pending');
const cancelled = await duty.cancelSelection(actor, pending.selection_id, requestB);
assert.equal(cancelled.picked[0].student_id, pending.picked[0].student_id);
const current = await duty.getRound(roundId);
await assert.rejects(
  () => duty.closeRound(actor, roundId, current.version, requestC),
  (err: unknown) => err instanceof AppError && err.code === 'DUTY_SELECTION_OPEN',
);
```

缺席第二次拒绝也要断言具体错误码，不能只断言抛了 `AppError`。

### 2. 改密明文令牌写入幂等表

- **文件与行号**：`src/services/auth.ts` 第 104–129 行；`src/services/idempotency.ts` 第 124–130 行
- **严重等级**：高
- **问题描述**：`changePassword` 把 `{ token }` 当作幂等函数的返回值。这个明文会话令牌会写入 `idempotency.response_body`，并随数据库备份保留到清理任务跑完。会话表里只存哈希，这条路径把仍有效的 Cookie 放进了备份。
- **修复建议**：幂等记录只保存 `{ ok: true }`。第一次响应用事务里新建的令牌设置 Cookie。同一 `request_id` 重放时不再签发令牌；客户端若没拿到 Cookie，用新密码重新登录。

```ts
await authRepo.revokeAllSessions(tx, teacherId);
const created = await authRepo.createSession(tx, { /* ... */ });
await auditRepo.writeAudit(tx, { /* ... */ });
return { ok: true as const, token: created.token };
```

在 `idempotentTx` 之外设置 Cookie，传入幂等存储的响应体改为 `{ ok: true }`，不要把 `token` 交给 `markDone`。

### 3. 匿名账本锁文件崩溃后永久占住

- **文件与行号**：`src/services/anonLedger.ts` 第 135–155 行
- **严重等级**：高
- **问题描述**：锁用 `wx` 创建，只在 `finally` 里删除。进程在持锁期间退出后，锁文件会留下。之后每次追加都空等 5 秒，然后抛「匿名账本锁等待超时」，不会删除过期锁。匿名化从这一次崩溃起一直失败。
- **修复建议**：等待前如果锁文件修改时间已经超过持锁上限，就删掉再抢。抢到之后仍在 `finally` 里关闭并删除。

```ts
const info = await stat(lockPath).catch(() => null);
if (info && Date.now() - info.mtimeMs > 5_000) {
  await rm(lockPath, { force: true });
}
```

### 4. 空池任命不校验学生是否属于该班

- **文件与行号**：`src/services/duty.ts` 第 410–433 行
- **严重等级**：高
- **问题描述**：候选池为空时，请求体里的 `student_id` 直接插入这条卫生线的 `duty_term`。外键只要求学生存在，不要求是本班在班学生。其他班的学生可以被任命为本班卫生管理员。这条路径也没有发 `duty_round_changed`。
- **修复建议**：任命前确认学生属于 `round.class_id` 且 `status = 'active'`。插入成功后调用已有的 `broadcast`。

```ts
const student = await tx.execute<{ class_id: string; status: string }>(
  sql`SELECT class_id, status FROM student WHERE student_id = ${studentId}`,
);
if (student[0]?.class_id !== round.class_id || student[0]?.status !== 'active') {
  throw Errors.notFound('本班在班学生', studentId);
}
```

### 5. 纠正任期收下 `expected_version` 但没有使用

- **文件与行号**：`src/services/duty.ts` 第 570–606 行；`src/lib/schema.ts` 第 707–714 行
- **严重等级**：中
- **问题描述**：`.cursorrules` 要求卫生轮次写入携带 `expected_version`。纠正接口的请求体有这个字段，服务只把它放进幂等哈希，不和任何版本比较。两台设备可以同时纠正同一任期。冻结、取消、确认、重新打开同样没有版本比较。
- **修复建议**：纠正、冻结、取消、确认、重新打开都锁住对应轮次，版本不一致时返回 `VERSION_CONFLICT`。没有轮次版本可对的操作不要在契约里要求 `expected_version`。

### 6. 卫生规则写在服务层的 SQL 里

- **文件与行号**：`src/services/duty.ts` 全文；`src/services/points.ts` 第 625–634 行
- **严重等级**：中
- **问题描述**：调用方向应是 `services → repo`，SQL 留在 `src/repo`。卫生轮次的增删改都写在服务里。排行榜查询也在 `listLeaderboard` 里直接 `db.execute`，旁边的 `src/repo/points.ts` `listRanked` 是另一套实现，服务没有用它。两套查询以后会分叉。
- **修复建议**：卫生读写移到 `src/repo/duty.ts`。排行榜只走 `listRanked`，在班过滤和并列名次保持一处。

### 7. 排行榜测试没有碰到在班过滤

- **文件与行号**：`test/leaderboard.test.ts` 第 5–20 行
- **严重等级**：低
- **问题描述**：`assignRanks` 的 `1, 1, 3` 断言是真的。它不查询数据库，因此证明不了离班学生会被排除。服务层的 `WHERE s.status = 'active'` 目前写对了，但没有测试守住。

## 3. 已关闭的 001 阻断项

- 登录失败在独立事务提交；同一用户名或同一 IP 满 5 次返回 429；锁定时不再增加失败行。见 `test/auth.integration.test.ts`。
- 改密撤销全部旧会话并签发新 Cookie；旧令牌访问 `/auth/me` 得到 `SESSION_REVOKED`。
- 新建和修改学生的审计写入不再保存姓名、学号；`listAudit` 会再删一次 `student_no` 和学生实体上的 `name`。
- 时间线用 `limit + 1` 计算 `next_cursor`。`include_reversals=false` 不再被布尔强制转换吞掉。
- 记分重复 `student_id` 会拒绝。分值方向使用 `POLARITY_MISMATCH`，前后端错误码已对齐。

## 4. 给开发会话的修复指令摘要

卫生集成测试要真的取消抽选并断言抽中的人不变，再用当前版本关闭仍为 `pending` 的轮次，断言 `DUTY_SELECTION_OPEN`。改密幂等响应不要保存会话明文。匿名账本锁文件按修改时间回收，避免一次崩溃后永久抢锁失败。空池任命必须是本班在班学生，并广播 `duty_round_changed`。纠正和冻结要校验 `expected_version`。在这些测试失败得了之前，不要把卫生轮次标成完成。
